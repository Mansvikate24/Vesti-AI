Six-Layer Fashion-Tech Architecture

Our stack decouples the client-side computer vision engine from backend cloud databases for low latency and privacy-friendly in-browser inferencing.

🖥️ Layer 1: User Interface

HTML5: Provides semantic structuring for all pages (landing, try-on studio, catalog, checkout, admin portal).
CSS3: Drives custom glassmorphic styling, responsive multi-column layouts, smooth animations, and cohesive HSL color tokens.
JavaScript (ES6+): Handles reactive DOM updates, try-on stage coordination, cart state persistence, and Firebase event subscriptions without heavy frontend framework overhead.

Implemented and Tested
🔐 Layer 2: Auth & Database

Firebase Authentication: Secure email/password account creation, session tokens, and route protection.
Cloud Firestore: Stores structured product records, user profiles, wishlist arrays, and order history.
Firebase Storage: Houses approved high-resolution dress photos and transparent PNG overlay assets.
Firestore Security Rules: Enforce role-based access control to protect administrative operations from unauthorized client writes.

Implemented and Tested
📷 Layer 3: Camera & AI

Browser Camera API: Queries navigator.mediaDevices.getUserMedia() after user consent.
MediaPipe Pose Landmarker: Detects 33 body landmarks (shoulders, elbows, hips, knees) in real-time.
HTML5 Canvas API: Dynamically calculates garment position, shoulder width, scale, and affine orientation to draw overlays.
TensorFlow.js / WebGL: Supported runtime environment for client-side ML tensor ops; WebGL/Three.js reserved for future 3D meshes.

Implemented and Tested
📱 Layer 4: QR Code System

Product Identification: Physical hangtags embed unique product IDs.
In-Browser QR Decoding: JavaScript scanner reads QR codes through the camera, extracts the garment ID, validates the record against Firestore, and redirects immediately to the interactive try-on room.

Implemented and Tested
🛍️ Layer 5: E-Commerce Funnel

Catalog & Inventory: Real-time dress search, category filtering, stock availability flags.
Cart & Wishlist: Local and Firestore synchronized shopping bag with quantity incrementation and price validation.
Checkout & Orders: Delivery address collection, Cash on Delivery support, and a transparent simulated UPI flow.

Implemented and Tested
🛡️ Layer 6: Deployment & Security

HTTPS Protocol: Strictly required by modern browsers to authorize camera access.
Firebase Hosting / Static CDNs: Global CDN edge caching with instant SSL certification.
Secret Sanitization: Frontend scripts contain only public Firebase client identifiers; no server credentials, administrative tokens, or private payment secrets are bundled in public client bundles.

Implemented and Tested
CRITICAL ENGINEERING CLARITY

Pose Landmark Alignment vs. 3D Cloth Simulation

A major pitfall in fashion tech marketing is exaggerating visual overlays as "exact fit tailor replicas". Here is our honest technical comparison:

✅ What Vesti-AI Currently Implements

  • • 2D Torso Landmark Tracking: Uses left/right shoulders (indices 11, 12) and hips (indices 23, 24) to estimate body width and vertical torso span.
  • • Perspective Affine Scaling: Garment dimensions scale proportionally with distance from the camera.
  • • Manual Tailor Fit Adjustments: Sliders allow the user to fine-tune garment scale (0.75x–2.4x), vertical offset (-100px to +100px), and opacity.
  • • Zero Latency Client-Side Privacy: Video frames stay on device, eliminating expensive cloud server GPU pipelines.

🔬 Requirements for True 3D Cloth Physics

  • • Dense Volumetric Mesh: Reconstructing the user's 3D body mesh (SMPL / SMPL-X models) rather than 2D points.
  • • Finite Element Cloth Deformation: Simulating physical fabric properties (silk drape vs. stiff denim tension) in real-time.
  • • Self-Occlusion & Depth Estimation: Hiding garment parts when arms cross in front or when the user turns sideways.
  • • Diffusion-Based Virtual Try-On: Neural GAN or diffusion inpainting (e.g. TryOnDiffusion), which requires cloud GPU clusters with 3–10s latency per frame.
